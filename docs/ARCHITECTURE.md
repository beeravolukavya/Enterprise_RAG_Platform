# Architecture decision record

Browser (React/Vite) -> Cognito authentication -> API Gateway JWT authorizer -> Lambda API.

Upload: API returns presigned S3 PUT; browser uploads directly to private S3; S3 event -> SQS -> Lambda worker -> extract -> chunk -> Titan embeddings -> OpenSearch Serverless VECTORSEARCH index. DynamoDB tracks status. Query: API embeds question -> tenant-filtered kNN -> Bedrock Converse -> answer + evidence.

## Trust boundaries
- Never accept tenant ID from browser; derive from verified Cognito JWT subject.
- Upload keys are generated by server, not browser.
- All document operations are scoped to subject; retrieval applies a tenant filter.
- Bedrock prompt treats document text as untrusted evidence.
- S3 private, TLS enforced, encrypted; DynamoDB PITR; CloudWatch logs.

## Production limitations / engineering backlog
- Search collection network access is public (IAM/SigV4 protected); move to VPC endpoints for strict environments.
- No delete/reindex or version reconciliation; implement tombstones and deterministic cleanup.
- Chunk writes are not transactional; partial failed ingestion may leave orphan chunks. Implement staging index and atomic alias switch.
- Cognito admin-managed users; no SSO federation or role hierarchy.
- No per-document ACL beyond per-user workspaces.
- No OCR for scanned PDFs, no virus scanning, no MIME sniffing.
- No automated groundedness scoring, rate limits, quota management, cost budgets, distributed tracing, or citation verification.
- Vector-only retrieval; add lexical BM25, reciprocal rank fusion, reranking and quality evaluation.
- S3 upload max is enforced by worker, not presigned PUT itself; enforce size with presigned POST policies or edge constraints.
- For enterprise use, add IaC policy tests, security scans, red-team tests, disaster recovery, load tests, and service-level objectives.
